NOVA STORE - تحديث النسخ الاحتياطي والاستعادة (V60)

التغييرات:
- أصبح زر /admin/export_backup ينزّل ملف ZIP شاملاً قاعدة البيانات (كل جداول SQLAlchemy) وكامل مجلد static.
- يشمل ذلك صور المنتجات والأقسام والبنرات والملفات الموجودة في static/uploads وأي ملفات static أخرى.
- يحتوي ZIP على manifest.json مع أحجام الملفات وبصمات SHA-256 للتحقق من سلامتها.
- /admin/import_backup يقبل ZIP الجديد وCSV القديم.
- يجري التحقق من ZIP وCRC والملفات والبصمات والمسارات قبل تغيير قاعدة البيانات أو الملفات.
- تمنع الاستعادة المسارات المطلقة ومسارات .. والروابط الرمزية والملفات خارج static.
- يتم استبدال مجلد static ضمن معاملة استعادة قاعدة البيانات مع الاحتفاظ بنسخة مؤقتة من الملفات الحالية لإرجاعها عند الفشل.
- CSV القديم ما زال مدعوماً لكنه لا يحتوي على الصور والملفات.
- يوجد رابط منفصل لتنزيل CSV القديم: /admin/export_backup_csv.

ملاحظات تشغيل:
1. ارفع المشروع إلى Render بالطريقة المعتادة وثبّت requirements.txt كما هو.
2. لا تغيّر DATABASE_URL أو SECRET_KEY عند النشر إذا كنت تريد الاحتفاظ بقاعدة البيانات والجلسات الحالية.
3. خذ نسخة ZIP من لوحة الإدارة قبل أي استعادة.
4. اختبر الاستعادة أولاً على خدمة/قاعدة بيانات تجريبية منفصلة؛ الاستعادة تستبدل سجلات الجداول وملفات static الحالية بمحتويات النسخة.
5. مساحة تخزين Render المؤقتة قد لا تبقى بعد إعادة النشر ما لم تكن static على Persistent Disk أو تخزين دائم. هذه النسخة تنقل الملفات بين النسخ، لكنها لا تغيّر بنية الاستضافة أو إعدادات التخزين الدائم.

حدود الأمان:
- الحد الأعلى لرفع النسخة 512MB.
- حد إجمالي الملفات بعد فك الضغط 1GB، وحد الملف الواحد 100MB، وقاعدة البيانات 200MB، وmanifest 5MB.
- النسخ تحتوي بيانات حساسة (حسابات، طلبات، بيانات إدارية)، لذا خزّن ZIP بمكان خاص ولا تشاركه علناً.
