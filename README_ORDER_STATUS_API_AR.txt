تحديث مزامنة حالة الطلبات والتحكم الإداري — NOVA STORE

- عند إنشاء طلب تلقائي عبر SMM، يحفظ الموقع رقم الطلب الذي يرجعه مزوّد API.
- تُحدّث الحالات المعروفة من API (قيد الانتظار، قيد التنفيذ، مكتمل، فشل الطلب، إلخ) في صفحة طلباتي ولوحة الإدارة.
- لوحة الإدارة تعرض كل الطلبات المسجلة، وسعر الطلب المعتمد من NOVA STORE من الحقل total_price، وليس تكلفة المزوّد.
- أثناء بقاء لوحة الإدارة مفتوحة، تُطلب مزامنة الحالات تلقائياً كل 45 ثانية. تُفحص دفعة محدودة من الطلبات التلقائية النشطة لتجنّب تعطيل تحميل الصفحة.
- يمكن للإدارة تحديد الطلب كمكتمل، أو رفضه مع كتابة السبب وإرجاع سعر الموقع إلى رصيد العميل، أو استرداد المبلغ مباشرة.
- الاسترداد محمي بعلامة دائمة وتحديث ذري في قاعدة البيانات حتى لا يُضاف المبلغ مرتين. حالات API الفاشلة/الملغاة/المستردة تعيد سعر الموقع مرة واحدة، مع إبقاء الحالة معبّرة عن نتيجة API.
- بعد تدخل الإدارة يثبت الاختيار اليدوي ولا تسمح مزامنة API بتغييره تلقائياً.
- أُضيفت الحقول admin_status_override و refunded و status_note بترحيل آمن لا يحذف بيانات الطلبات القديمة.

مهم: يجب أن يدعم مزوّد الخدمة صيغة SMM الشائعة: action=add لإنشاء الطلب و action=status مع order=رقم طلب المزوّد للاستعلام عن حالته. إذا كانت صيغة المزوّد مختلفة، يلزم تكييف دالة الاستعلام حسب توثيقه.
